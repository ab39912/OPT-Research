# Cross-Dataset Comparison

Generated by `cross_dataset.py` on the three real files. All type, null, and
cleaning decisions come from the shared `datakit` module, so these figures are
consistent with the per-dataset scripts. Regenerate with:

```bash
python cross_dataset.py \
    2024_fb_ads_president_scored_anon.csv \
    2024_fb_posts_president_scored_anon.csv \
    2024_tw_posts_president_scored_anon.csv \
    --labels ads fb_posts tw_posts
```

## How to read this

**The 27 shared columns are all the `*_illuminating` classifier flags** — the
same content model (message type, call-to-action, 15 topics, incivility, scam,
fraud) was applied across ads, Facebook posts, and tweets. That makes the shared
set a genuine cross-platform comparison of *what the political content was
about*, even though the platform-native metrics (spend, likes, retweets) are not
shared. Compare **prevalence rates** (the mean of each 0/1 flag) across the three
columns below.

Headline differences from those shared flags:

- **Economy leads everywhere but peaks on Twitter** (~16% of tweets vs ~12% of
  ads vs ~9% of FB posts).
- **Paid ads push health and women's issues harder than organic content does**
  (health ~11% in ads vs ~5% in posts/tweets; women's issues ~8% vs ~2–3%) —
  campaigns pay to raise issues that don't surface as much in organic feeds.
- **Attack messaging is most common on Twitter** (~31%) and least on FB posts
  (~22%); **advocacy is strikingly constant** (~55%) on all three.

**Data-quality catch (surfaced automatically):**
`election_integrity_Truth_illuminating` shows up under "only in ads" and "only
in tw_posts" but **not** in the shared set — because in the Facebook-posts file
its header is malformed, fused to the previous column as
`illuminating_scored_messageelection_integrity_Truth_illuminating`. The
comparison tool made this integration bug visible without anyone looking for it,
which is a good argument for running a mechanical cross-schema check before
trusting "shared" columns. A one-line rename in the posts file would move that
column into the shared set.

The generated overview, full shared/unique column lists, and per-column tables
follow.
